# ASAF and AEOF Appendix Design Pack

**Updated:** June 8, 2026  
**Purpose:** Define how the appendices for the ASAF and AEOF ebooks should be structured, what each appendix should contain, and how they should support the main manuscript without overwhelming it.

---

## Why appendices matter here

Both books are built on frameworks with substantial structural detail:

- principles
- maturity stages
- dimensions and sub-dimensions
- scoring logic
- transformation models
- evaluation guidance

If too much of this material remains in the body chapters, the manuscript risks feeling like documentation instead of a book. The appendix strategy solves that problem.

### The appendices should do three jobs

1. preserve rigor without slowing narrative pace
2. give power users reference depth when they want it
3. turn the books into reusable working assets, not just arguments

---

## Shared appendix design principles

### Principle 1 — Every appendix must have a job

No appendix should exist just because it might be useful. Each appendix should answer one of these questions:

- what is the precise framework reference?
- how do I assess something with this framework?
- how do I use this framework in real decision-making?
- what terms do I need to understand to use the book correctly?

### Principle 2 — Appendices should feel tool-like

Readers should be able to use appendices as:

- working references
- workshop handouts
- assessment sheets
- internal planning aids

### Principle 3 — Prefer durable artifacts over prose overflow

The strongest appendices will often be:

- tables
- scorecards
- checklists
- glossaries
- maturity rubrics
- visual summaries

### Principle 4 — Avoid duplicating the body verbatim

Appendices should complement the book, not reprint it in more tedious form.

---

## Shared appendix architecture

Both books should use a similar appendix structure so the pair feels coherent.

### Recommended appendix families

1. framework core reference
2. maturity model reference
3. dimension and sub-dimension guide
4. assessment tools
5. diagnostic or evaluation worksheets
6. glossary and terminology

## ASAF appendix pack

### Appendix A — ASAF principles reference

**Purpose:** preserve the eight ASAF operating principles in a clean reference form without overloading the body chapters.

**Should include:**

- principle ID
- principle label
- exact statement
- plain-language interpretation
- why it matters operationally

**Best format:** a compact table with columns for principle, statement, and meaning.

### Appendix B — ASAF maturity-stage model

**Purpose:** give the reader a compact but complete stage ladder.

**Should include:**

- stage name
- tag
- autonomy model
- human model
- governance model
- detection posture
- knowledge posture
- typical timing window

**Best format:** one row per stage plus a one-page ladder visual.

### Appendix C — ASAF dimension and sub-dimension glossary

**Purpose:** provide a complete reference map of all 11 dimensions and their sub-dimensions.

**Should include:**

- dimension name
- one-sentence description
- sub-dimension names
- assessment question
- one-line interpretation

**Best format:** dimension-by-dimension sections with compact sublists.

### Appendix D — ASAF stage-assessment worksheet

**Purpose:** turn the framework into a practical assessment instrument.

**Should include:**

- current stage estimate
- target stage in 18–24 months
- strongest dimensions
- weakest dimensions
- structural blockers
- platform gaps
- governance blockers

**Best format:** a fillable worksheet or scorecard table.

### Appendix E — ASAF vendor-category diagnostic checklist

**Purpose:** operationalize the Enabler / Neutral / Displaced logic.

**Should include questions such as:**

- Does the vendor contribute to Stage 2+ advancement?
- Does it write back to the SKG?
- Does it shape GOV or AGT capabilities?
- Does it depend on alert-centric workflows remaining unresolved?
- Is its value reduced or increased at Stage 3?

**Best format:** checklist with scoring bands and category thresholds.

### Appendix F — ASAF buyer evaluation questions

**Purpose:** translate the framework into buyer-ready evaluation prompts.

**Should include question groups for:**

- detection vendors
- SOC platform vendors
- orchestration and execution platforms
- governance and audit capabilities
- integration and graph depth

**Best format:** question bank grouped by dimension or buyer role.

## AEOF appendix pack

### Appendix A — AEOF principles reference

**Purpose:** present the eight AEOF principles in clear, reader-friendly form.

**Should include:**

- principle label and statement
- plain-language translation
- operating-model implication
- what old assumption it replaces

### Appendix B — AEOF maturity-stage model

**Purpose:** show how enterprise operations evolves from queue-centric operations to an autonomous operating system.

**Should include:**

- stage name and tag
- autonomy level
- human model
- governance model
- operational posture
- knowledge model
- likely transformation signal

**Best format:** table plus stage-ladder visual.

### Appendix C — AEOF dimension reference guide

**Purpose:** provide a complete operational map of all 11 AEOF dimensions and sub-dimensions.

**Should include:**

- dimension description
- sub-dimension names
- core assessment question
- one-line interpretation of higher maturity

**Suggested grouping:**

- sensing / reasoning / action / governance
- learning / operations / human / agents / knowledge
- assurance / transformation

### Appendix D — AEOF transformation journey by phase

**Purpose:** turn the framework into a programmatic change roadmap.

**Should include:**

- stage range
- approximate duration
- key activities
- inflection points
- major failure modes
- leadership implications

**Best format:** one section per phase with quick-scan tables.

### Appendix E — AEOF failure-mode checklist

**Purpose:** give leaders a concrete way to discuss agentic-operations risk.

**Should include categories such as:**

- governance theater
- policy drift
- automation debt
- graph irrelevance
- cross-domain coordination failure
- explainability breakdown
- trust collapse
- fallback atrophy

**Best format:** failure mode × signal × consequence × mitigation matrix.

### Appendix F — AEOF readiness assessment worksheet

**Purpose:** help readers assess whether their organization is ready for AEOF-style transformation.

**Should include:**

- leadership alignment questions
- cultural readiness questions
- technical debt questions
- data and integration readiness questions
- governance maturity questions
- resilience and override questions

**Best format:** scored worksheet with interpretation bands.

## Cross-book appendix reuse opportunities

These two books should share certain appendix templates to reduce effort and reinforce brand consistency.

### Reusable pattern 1 — Maturity ladder template

Use the same visual grammar across both books:

- stage number
- stage label
- defining behavior
- leadership implication

### Reusable pattern 2 — Dimension reference template

Use the same section structure across both books:

- dimension definition
- why it matters
- what higher maturity looks like
- evaluation question

### Reusable pattern 3 — Assessment worksheet template

Use the same worksheet logic:

- current state
- desired state
- blockers
- evidence
- next action

### Reusable pattern 4 — Diagnostic checklist template

Use the same checklist logic:

- yes / partly / no
- evidence required
- implication if missing

1. Principles
2. Maturity model
3. Dimension reference
4. Transformation or journey material
5. Diagnostic worksheets

It moves from conceptual reference to practical application.

## Markdown and export guidance

If these appendices stay in Markdown first and export later, design them to preview well.

### Use generously

- short headings
- compact tables
- numbered lists
- section dividers
- simple reference callouts

### Avoid

- giant uninterrupted tables where smaller grouped tables would scan better
- long prose blocks in appendices
- repeating definitions the body already explains well

---

## Recommended production sequence

Build in this order:

1. maturity model appendix
2. dimension glossary appendix
3. assessment worksheet appendix
4. diagnostic checklist appendix
5. glossary
6. visual appendix polish

### Why this sequence works

It creates the most reusable support assets fastest.

---

## Final appendix philosophy

The appendices should make the books more useful, not just longer.

If the body chapters make the reader believe the argument, the appendices should make the reader able to **use** it.

That is the test.
